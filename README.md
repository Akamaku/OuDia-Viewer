# 発車案内表示機 (OuDia Viewer)

OuDia / OuDiaSecond の路線ファイル(`.oud` / `.oud2`)を読み込んで、駅・バス停ごとの
**リアルタイム発車案内**と**時刻表ブラウザ**を表示する、静的サイトです。
ビルド不要・サーバー不要。フォルダごとGitHub Pagesなどにアップロードするだけで動きます。

## フォルダ構成

```
oudia-board/
├── index.html          表示画面本体
├── css/style.css        デザイン
├── js/
│   ├── oudia-parser.js  OuDia形式のパーサー(汎用)
│   └── app.js            画面ロジック(読込・リアルタイム計算・描画)
└── oud/
    ├── manifest.json     読み込む.oudファイルの一覧
    └── sample.oud         動作確認用サンプルダイヤ
```

## 自分の路線ファイルを追加する

1. OuDia / OuDiaSecond で作成した `.oud` ファイルを `oud/` フォルダに置く
   (Shift_JIS / UTF-8 どちらの文字コードでも自動判定して読み込みます)
   - **ファイル名は半角英数字を推奨します**(例: `route8.oud`)。日本語ファイル名だと、
     Gitでコミットした際やOS間でのUnicode正規化(NFC/NFD)のずれにより、
     `manifest.json`に書いた名前と実際のファイル名が一致せず404になることがあります。
     表示名は下記の`label`で日本語のまま指定できるので、ファイル名自体は英数字にしてください。
2. `oud/manifest.json` に1行追加する

```json
[
  { "file": "oud/aonami-kousoku.oud", "label": "青波高速線" },
  { "file": "oud/sample.oud", "label": "青波シティバス 3系統(サンプル)" },
  { "file": "oud/route8.oud", "label": "8系統 柳町循環" }
]
```

3. `index.html` を開く

### ⚠️「Failed to fetch」と出て何も表示されない場合

`index.html` を **ダブルクリックして `file://...` として直接開いている**のが原因です。
ブラウザはセキュリティ上の理由で `file://` からの `fetch()`(=manifest.jsonや.oudファイルの読み込み)をブロックします。
ローカルで確認する場合は、必ず簡易サーバー経由で開いてください。

```bash
# oudia-board フォルダの中で実行
python3 -m http.server 8000
# → ブラウザで http://localhost:8000 を開く
```

VSCodeを使っている場合は「Live Server」拡張機能で開くのが簡単です。
**GitHub Pagesで公開した場合はこの問題は起きません**(常にhttp(s)経由になるため)。

## GitHub Pagesで公開する

1. このフォルダの中身をそのままリポジトリのルート(または `/docs`)にpush
2. GitHubリポジトリの Settings → Pages で公開ブランチ・フォルダを指定
3. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

既存の青波シティバスのシステム(GitHub Pages + GAS)と同じ構成なので、
同一リポジトリ内の別ディレクトリとして共存させることも可能です。

## 画面の機能

- **路線ファイル / ダイヤ / 駅・バス停** をプルダウンで切り替え
- **方向フィルタ**: すべて / 下り / 上り
- **表示モード**
  - リアルタイム: **パタパタ(反転フラップ)式のみ**。実機の反転フラップ表示機を模したスタイルで、
    **直近3本を発車順(直近が上)に表示**し、**発車時刻のみ**を表示します(到着時刻は表示しません)。
    直近の列車が3本に満たない場合も**枠は常に3段分表示**し、列車が割り当たらない段は空欄コマのままにします。
    種別・行先は単語ごと1枚のコマとして扱います。あらかじめ用意したコマ(印字パネル)に無い単語は空欄(無表示)になります。
    コマの元になる単語一覧は `js/app.js` の `FLAP_TYPES` / `FLAP_DESTINATIONS` / `FLAP_MAX_HOUR`(時は00〜28まで)で
    自由に編集できます。値が変わるときは実機同様、現在のコマから目的のコマまで**1つずつ順番にめくって**止まり、
    着地の瞬間だけ軽く跳ねます。**表示枠(3段)に収まる範囲の、実際に発車が近い列車のみを表示します**
    (発車時刻に関係のないコマの動きは起きません)。時・分は独立したコマですが、**見た目はひとつの枠にまとめて**
    表示しています。
  - 時刻表: 選択駅の発車を時刻順に一覧表示。**種別・行先で絞り込み**が可能です
- **行をクリック/タップすると、その列車1本だけの時刻表(各駅の発車時刻)がモーダルで開きます**
  (通過駅は「レ」、運行区間外の駅は「−」で表示)
- **パタパタの種別コマは全種別とも白字・黒背景で統一**しています(色分けはしていません)。
  時刻表・モーダル側の種別バッジは引き続き色分け表示です: 普通=青、急行・通急(通勤急行と同じ扱い)=オレンジ、
  区間急行=緑、特急=赤、ライナー=茶色。それ以外の種別は`.oud`ファイル内の
  `JikokuhyouMojiColor`設定(無ければ既定色)をそのまま使います。配色を変えたい場合は
  `js/app.js` 冒頭の `TYPE_COLOR_OVERRIDES` を編集してください。
- `FLAP_TYPES` には「船渡川から普通 特急」のような **"〜からXY" 形式の複合種別**も登録できます。
  パタパタでは上下分割せず、「〜から」「X」を左に小さく2段、既知の種別名に一致する末尾(Y)を右に大きく表示します。
- **運休(unkyu)など、そもそも運行されない種別のみ発車案内・時刻表から除外します**(`HIDDEN_TYPES`で管理)。
  回送・通過・臨時・団体・試運転は種別として実際に表示されます。
- **通過(停車しない)駅では、その列車を発車案内・時刻表のどちらにも表示しません**(乗車できないため)。
  列車単体の時刻表モーダルでは、通過駅は「レ(通過)」と表示されます。
- **現在時刻を使用** のチェックを外すと、指定した時刻を起点に時計が進み続けます(リアルタイム表示と同様に
  1秒ごとに更新され、ヘッダーの時計・発車案内どちらにも反映されます)。深夜帯のダイヤ確認や動作確認に便利です。
- パタパタ表示は `Hiragino Kaku Gothic ProN` / `Hiragino Sans`(macOS・iOS標準)を優先して使用し、
  無い環境ではシステムのゴシック体にフォールバックします。

## OuDiaファイル形式について(このツールが解釈する範囲)

OuDia形式は「`Xxx.`で始まり単独の`.`で閉じる」階層構造 + `key=value` のテキスト形式です。
このビューアでは以下を読み取ります。

- `Rosen.` 内の `Eki.`(駅)、`Ressyasyubetsu.`(列車種別)、`Dia.`(ダイヤ)
- 各 `Dia.` 内の `Kudari.` / `Nobori.` それぞれの `Ressya.`(列車)と `EkiJikoku`(各駅時刻)
- `EkiJikoku` は駅ごとに `,` 区切り、各駅は基本的に `フラグ;着時刻/発時刻` の形式(`;`前のフラグ自体は表示に使用していません)
  - 例: `1;810/815` = 着8:10・発8:15、`1;830/` = 着8:30のみ(終着)、`1;800` = 発8:00のみ、`2` = 通過(時刻なし)
  - **時刻の内部表現は「時+分(2桁)+秒(2桁)」を連結した数値**で、秒が0の場合は末尾2桁が省略されます
    (例: `447`→4:47:00、`44530`→4:45:30)。実データ数千件で突き合わせて検証済みです
  - 深夜帯は `2530` のように24時以降の数値がそのまま入っている前提で計算します(秒表現でも同様)

### 既知の制限

- **分岐駅・環状線(ループ)には対応していません**。単純な一本の下り/上り路線を想定しています。
  複雑な路線網は、区間ごとに `.oud` ファイルを分けて `manifest.json` に複数登録する運用を想定しています。
- 番線(ホーム)情報や運行日パターン(平日/土休日以外の細かい条件)は現状表示していません。
  必要であれば `js/app.js` の `rowHtml()` まわりに項目を追加してください。
- `EkiJikoku` の先頭フラグ(通過種別など)は簡略化して扱っています。厳密な「通過」表示が必要な場合は
  `js/oudia-parser.js` の `parseEkiJikoku()` を拡張してください。

## カスタマイズのヒント

- 駅名を「バス停」名義にしたい場合は `index.html` 内の文言(「駅・バス停」等)を調整するだけでOKです。
- 停留所名の路線間重複を接尾辞で区別する運用をしている場合、`Ekimei` にそのまま接尾辞付きの名前を
  入れておけば、このビューアはそのまま表示に反映します。
- 配色は `css/style.css` の `:root` にある CSS変数(`--bg-void` 等)を変更するだけで一括変更できます。
